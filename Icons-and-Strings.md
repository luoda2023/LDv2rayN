# Icons-and-Strings

This document records the two non-negotiable UI conventions for LDv2rayN.
Every XAML view and view-model must follow them; new code that breaks the
rules should be rejected in review.

## 1. Icons: `materialDesign:PackIcon` only, no emoji

All icons in WPF views must use `materialDesign:PackIcon` with a
`Kind="..."` value from the MaterialDesignThemes icon set.

```xml
<!-- ✅ Correct -->
<materialDesign:PackIcon Kind="Server" Margin="{StaticResource MarginRight8}"
                         VerticalAlignment="Center" />

<!-- ❌ Wrong: emoji in a TextBlock -->
<TextBlock Text="🌐" FontSize="16" />
```

**Rationale.** Emoji glyphs are rendered by the OS emoji font (Segoe UI Emoji
on Windows, Noto Color Emoji on Linux). They depend on which font is
installed, are monochrome by default in WPF, and frequently fall back to a
colorless or empty glyph when the theme switches. `materialDesign:PackIcon`
is theme-following (Foreground inherits `DynamicResource`) and renders the
same glyph across light/dark themes and across Windows/Linux/macOS.

**Exceptions.** A *fixed* emoji that is part of a product name (e.g. a
brand wordmark) is allowed inside a non-interactive label. Anything on a
menu item, button, tab header, tray icon, or toolbar item counts as a UI
icon and must be a `PackIcon`.

## 2. UI strings: `resx:ResUI.<key>` only, no hard-coded text

All user-visible strings must come from
`ServiceLib/Resx/ResUI.resx` (and its per-locale siblings) via the
`x:Static` binding.

```xml
<!-- ✅ Correct -->
<MenuItem x:Name="menuAISetting"
          Header="{x:Static resx:ResUI.menuAiFetch}" />

<!-- ❌ Wrong: hard-coded Chinese/English literal -->
<MenuItem x:Name="menuAISetting" Header="🤖 AI智能获取" />
```

**Rationale.** Hard-coded strings skip the resource manager entirely, so:

- Users on `fa`, `ru`, `fr`, `hu`, `id`, `zh-Hant` locales see the
  developer's language, not their own.
- Adding a new locale requires editing every XAML view rather than adding
  one more `.resx` file.
- The string cannot be A/B tested or updated without a rebuild.

### Adding a new string

1. Pick a PascalCase key with the `menu` prefix for menus, `Tb` for
   toolbar items, `Msg` for messages, `Btn` for buttons, etc. Match the
   naming used by neighboring keys in `ResUI.resx`.
2. Add the `<data name="...">` entry to **all eight** `.resx` files:
   `ResUI.resx` (en default), `zh-Hans.resx`, `zh-Hant.resx`,
   `fr.resx`, `ru.resx`, `fa.resx`, `hu.resx`, `id.resx`.
3. Add the auto-generated property to `ServiceLib/Resx/ResUI.Designer.cs`
   (this file is regenerated by the designer; if you cannot run it, copy
   the pattern from a neighboring `public static string` property).
4. Reference it in XAML via `{x:Static resx:ResUI.<key>}`.

### Do not add emoji to `resx` values

Even inside `.resx` files, values must be plain text. Emoji icons
belong in the XAML as a separate `PackIcon` next to the label, not
baked into the string resource.

```xml
<!-- ✅ Correct: PackIcon + resx label -->
<MenuItem.Header>
    <StackPanel Orientation="Horizontal">
        <materialDesign:PackIcon Kind="AutoAwesome"
                                 Margin="{StaticResource MarginRight8}"
                                 VerticalAlignment="Center" />
        <TextBlock Text="{x:Static resx:ResUI.menuAiFetch}" />
    </StackPanel>
</MenuItem.Header>

<!-- ❌ Wrong: emoji baked into the resx string -->
<!-- ResUI.resx: <value>🤖 AI Fetch</value> -->
```

## Enforcement

- `grep -rn 'Header="[^\"]*['\\U0001F300-\\U0001FAFF\\u2600-\\u27BF]' v2rayN/Views/*.xaml`
  must return zero matches.
- `grep -rn 'Text="[^\"]*['\\U0001F300-\\U0001FAFF\\u2600-\\u27BF]' v2rayN/Views/*.xaml`
  must return zero matches (except where explicitly noted in a comment as
  a product wordmark).
- `grep -rnE 'Header="[^\{]" v2rayN/Views/*.xaml | grep -v resx`
  must return zero matches.

Run the three checks before committing a UI change.
